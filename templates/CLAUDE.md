# Контекст хранилища

> Шаблон файла правил для Claude Code. Положите его в корень своего
> хранилища Obsidian и перепишите под себя: первый абзац, примеры тегов
> и список плагинов — ваши, остальное можно оставить как есть.

Личная база знаний одного человека. Формат — Obsidian markdown, связи через
`[[wiki-links]]`, метаданные во frontmatter. Язык заметок и их имён — русский.

**Имена папок верхнего уровня** (перечислены в таблице ниже) — английские,
в нижнем регистре: на них ссылаются скрипты и эта инструкция. Их состав
фиксирован, новые не создаются.

**Подпапки внутри них** — на любом языке и в любом регистре, это личные
категории автора. Существующие подпапки в `areas/` **переименовывать не нужно** — ни в нижний
регистр, ни на английский.

Методология: **PARA** для раскладки, **CODE** для потока работы.

---

## Структура

| Папка | Что лежит | Признак |
|---|---|---|
| `inbox/` | сырой необработанный вход | `status: raw` |
| `daily/YYYY-MM/` | ежедневные заметки `YYYY-MM-DD.md` | разбиты по месяцам |
| `projects/<проект>/` | есть цель и срок, **папка на проект** | закрылся — в `archive/` |
| `areas/` | постоянная ответственность без срока | не закрывается никогда |
| `resources/` | справочное по темам | пригодится когда-нибудь |
| `archive/` | завершённое | не трогать без запроса |
| `assets/` | вложения, внутри `assets/excalidraw/` | не markdown |
| `private/` | **не читать, не индексировать, не изменять** | шифруется git-crypt |
| `templates/` | шаблоны Templater | синтаксис `<% %>` |

### Главное правило раскладки

Раскладывай по тому, **где заметка понадобится**, а не по тому, **о чём она**.
Конспект по SwiftUI, нужный для текущей задачи, идёт в `projects/<проект>/`,
а не в `resources/`. После закрытия проекта переезжает в `resources/`.

Непонятно, `projects/` или `areas/` — задай вопрос: «есть ли дата, когда это
считается завершённым?» Есть — `projects/`. Нет — `areas/`.

### Новый проект

Создаётся папкой: `projects/<короткое-имя>/`, внутри `index.md` с целью,
сроком и текущим статусом. Остальные заметки проекта — рядом в той же папке.

## Схема frontmatter

```yaml
---
created: 2026-09-13 09:40      # никогда не менять
source: telegram | obsidian    # никогда не менять
status: raw | processed        # raw ставит бот, processed ставишь ты
type: idea | task | reference | journal
tags: [swift, учёба]           # 1–4 тега, строчными, без #
due: 2026-09-20                # только если срок явно указан в тексте
---
```

`created` и `source` неприкосновенны.

## Именование файлов

- Имя = суть заметки по-русски, с пробелами.
  Хорошо: `Почему @StateObject не переживает пересоздание вью.md`
  Плохо: `zametka-1.md`, `swift_notes_final.md`
- Даты в имени только в `daily/`.
- Не использовать `/ \ : * ? " < > |` — сломают синхронизацию.
  Пробелы и кириллица допустимы, они работают везде.
- **Не переименовывай файл, не проверив, кто на него ссылается.** Порядок:
  `grep -rl "старое имя" --include="*.md" .` → переименование → правка
  ссылок. Битые `[[ссылки]]` — самая частая поломка здесь.

## Команда /process-inbox

Запускается вечером вручную. Порядок:

1. Прочитай все файлы из `inbox/` со `status: raw`.
2. Для каждого определи `type` и предложи целевую папку по PARA.
3. Предложи новое имя файла.
4. Заполни `tags`, `status: processed`, при явном сроке — `due`.
5. Найди родственные заметки и предложи блок `## Связи` с `[[ссылками]]`.
6. Собери отдельным списком все найденные даты в виде готовых команд,
   но **не выполняй их**:
   `~/bin/add-event.sh "Название" "YYYY-MM-DD HH:MM" 60 "brain"`
7. Найди файлы-дубликаты конфликтов iCloud (имена вида `заметка 2.md`),
   покажи различия, предложи слияние.
8. **Выведи весь план и остановись. Ничего не применяй без явного
   подтверждения.**
9. После подтверждения примени и выведи отчёт: сколько обработано,
   куда разложено, что осталось непонятным.

### Особый случай: заметки, перенесённые из старого vault

В `inbox/` могут лежать заметки, перенесённые из старого хранилища при
миграции, — у них нет frontmatter и `status`. Их разбирай тем же порядком, но:

- поле `created` бери из даты изменения файла;
- `source: obsidian`;
- если заметка явно устарела (прошедший экзамен, закрытая поездка) —
  предлагай `archive/`, а не выдумывай для неё место.

## Жёсткие запреты

1. **Не трогай `private/`** — не читать, не открывать, не упоминать
   содержимое. Она зашифрована git-crypt намеренно.
2. **Не трогай `.obsidian/`, `.git`, `.trash/`, `.claude/`.**
3. **Ничего не удаляй.** Перемещение в `archive/` — да, `rm` — нет,
   ни при какой формулировке задачи.
4. **Не переписывай текст заметок.** Ты правишь метаданные, имена и
   раскладку. Формулировки автора — его собственные, в них ценность.
   Исключение: явные опечатки и оформление перечисления списком.
5. **Не создавай заметки за автора.** Сгенерированный конспект вместо
   написанного своими словами обесценивает всю систему.
6. **Не применяй массовые изменения без подтверждения.** Больше трёх
   файлов за раз — сначала план, потом выполнение.
7. **Не добавляй события в календарь сам.** Только предлагай команды.
8. **Не пиши секреты в vault.** Токены, ключи, пароли — вне репозитория.
9. **Не коммить ключ git-crypt** и не копируй его внутрь vault.

## Стиль общения с автором

- По-русски, прямо, без смягчений и дежурных оговорок.
- Задача сформулирована противоречиво — скажи об этом до начала работы.
- Не уверен в раскладке конкретной заметки — не угадывай, вынеси её
  в список «требует решения» и спроси.
- Оценки честные, включая «эта заметка выглядит как мусор, предлагаю
  в архив».

## Плагины и их особенности

Установлены: Excalidraw, Kanban, Templater, Terminal, Git, Dataview,
Image Converter, Omnisearch.

- **Excalidraw** хранит рисунки в `.md` вместе с закодированными данными.
  Не редактируй их как текст, не переименовывай без крайней нужды.
  Лежат в `assets/excalidraw/`.
- **Kanban** хранит доски в markdown с особой структурой списков.
  Не «нормализуй» их форматирование.
- **Templater** использует синтаксис `<% %>`. Файлы в `templates/`
  не обрабатывай как обычные заметки.
- **Image Converter** конвертирует вставляемые картинки в WebP
  автоматически. Отдельно сжимать вставленное не нужно.
